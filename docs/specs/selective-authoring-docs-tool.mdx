# Selective authoring documentation MCP contract

**Status:** frozen for implementation

## Goal

Make version-matched workflow-script and REPL authoring documentation directly selectable by an agent through the MCP server, without requiring an installed skill, a prompt-capable host, filesystem access, or one giant context injection.

## Surface

The server registers a third model-facing tool named `docs` alongside `workflow` and `repl`. The app-only `workflow-events` tool remains hidden from the model where MCP Apps visibility is honored.

Input:

```ts
interface DocsToolInput {
  topic?: DocsTopicId; // default "index"
}
```

There is no action discriminator, projectDir, path, URL, query, topic array, offset, or limit. One call returns exactly one curated topic. `index` returns only the bounded topic catalog.

The closed topic ids are:

- `index`
- `workflow/quickstart`
- `workflow/run-lifecycle`
- `workflow/models-and-config`
- `workflow/composition-and-failure`
- `workflow/checkpoints-and-quality`
- `workflow/environment-and-tools`
- `workflow/determinism-and-resume`
- `workflow/api-agents`
- `workflow/api-control-flow`
- `workflow/api-resume-and-backends`
- `workflow/examples`
- `repl/quickstart`
- `repl/state-and-bindings`
- `repl/agent-handles`
- `repl/steering-queueing-and-cancellation`
- `repl/checkpoints-and-introspection`
- `repl/persistence-and-reset`
- `repl/api-reference`
- `repl/examples`

## Result

Every successful call returns exact structured metadata:

```ts
interface DocsToolResult {
  topic: DocsTopicId;
  title: string;
  description: string;
  uri: string;
  mimeType: "text/markdown";
  relatedTopics: DocsTopicId[];
  bytes: number;
}
```

The tool content includes one MCP embedded-resource block containing the exact topic markdown. It may also include one short text orientation line, but must not duplicate the document as a text block. The URI is `agentprism://docs/<topic>`.

Every topic is also registered as a static MCP resource with the same URI, metadata, MIME type, and byte-identical text. The model-facing tool is the reliable discovery/read path; resource listing is supplementary for hosts that expose resources.

## Bounds and safety

- `index` is at most 8 KiB UTF-8.
- Every other topic is at most 16 KiB UTF-8.
- Topic ids, titles, URIs, and related-topic links are unique and statically generated.
- Unknown topics fail at the MCP input-schema boundary and enumerate the closed alternatives.
- Calls are read-only, idempotent, require no project context, open no backend session, run no workflow/REPL code, persist nothing, and spend no model tokens.
- Documentation is bundled into the published server artifact and version-matched to its implementation.
- MCP-facing documents contain no terminal-only validator/config discovery instructions and no unresolved relative-file pointers.
- Workflow and REPL API references remain explicitly separated because their `agent()` signatures and lifecycle semantics differ.

## Source and drift

Canonical MCP topic sources live under `docs/authoring/`, independent of the optional authoring skill. A deterministic generator emits a checked-in TypeScript bundle under `packages/mcp-server/src/generated/`. CI compares a fresh generation byte-for-byte, enforces all bounds and links, and checks public workflow/REPL API vocabulary sentinels.

The optional `agentprism-workflow-authoring` skill remains available for non-MCP hosts, but the server neither reads nor embeds it. The `author-workflow` MCP prompt becomes a compact task-framing prompt that instructs the assistant to use the `docs` index and relevant topics; it no longer injects the complete skill.

## Tool-local guidance

`SERVER_INSTRUCTIONS` introduces `docs` as progressive disclosure. The `workflow` and `repl` descriptions retain the minimum safe executable contract and point to exact relevant topic ids for deeper syntax. Validation diagnostics remain directly actionable and never require a docs lookup to understand the correction.
