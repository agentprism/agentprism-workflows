# Skills over MCP authoring contract

**Status:** frozen for implementation

## Goal

Ship version-matched workflow and REPL authoring guidance with the MCP server through the accepted
SEP-2640 Skills Extension. Replace the model-facing `docs` tool completely: authoring guidance is
advertised as Agent Skills, activated through the host's skill-loading path, and read as standard MCP
resources only when needed.

This contract follows SEP-2640 at `modelcontextprotocol/modelcontextprotocol` commit
`d6b31a03504c15677d49b922b6b6ace0ef65728d`. The extension identifier is
`io.modelcontextprotocol/skills`.

## Served skills

The server publishes exactly two static skills:

- `skill://agentprism-workflow-authoring/SKILL.md`
- `skill://agentprism-repl-orchestration/SKILL.md`

They remain separate because workflow scripts and REPL evals have different `agent()` signatures,
syntax, state, and lifecycle semantics. Each source directory is itself a valid Agent Skill: its
`SKILL.md` frontmatter `name` matches the directory and URI authority, and its supporting references
resolve relative to that skill root.

Canonical sources live under `docs/authoring/`. The retired standalone
`skills/agentprism-workflow-authoring/` guide is not reused, served, or retained.

## Capability and methods

Legacy initialization and modern `server/discover` advertise:

```json
{
  "extensions": {
    "io.modelcontextprotocol/skills": {
      "directoryRead": true
    }
  }
}
```

Declaring the extension commits the server to these methods:

- `skills/list({ cursor? })` returns the two static skill entries with `resultType: "complete"`. The
  complete catalog fits one page, so no cursor is issued and any supplied cursor is invalid.
- `skills/get({ uri })` returns `resultType: "complete"` and the same entry shape for one exact served
  `SKILL.md` URI. Unknown URIs fail with MCP Invalid Params (`-32602`).
- `resources/directory/read({ uri, cursor? })` returns `resultType: "complete"` and the direct children
  of an exact skill directory. Directories use `inode/directory`, listings are non-recursive, and
  unknown/file URIs or unissued cursors fail with Invalid Params.

Every skill entry contains:

```ts
interface SkillEntry {
  uri: string;
  frontmatter: Record<string, unknown>;
  resources: Array<{ uri: string; digest: string; size: number }>;
}
```

The server serves no dynamic skill and no archive. `skill://index.json` is an obsolete pre-SEP
mechanism and is not registered.

## Resources and integrity

Every source file in a skill directory appears exactly once in its complete `resources` manifest and
is readable at that exact URI through standard `resources/read`. Text is served byte-identically to
the generated snapshot with its correct MIME type. Digests are SHA-256 over the raw served bytes,
formatted `sha256:<64 lowercase hexadecimal characters>`; `size` is the length of those same bytes.

The generated bundle is immutable for the server process, so the listing, `skills/get`, and resource
reads cannot drift from one another. Each skill remains within SEP-2640's 512-resource and 16 MiB
limits; this project additionally caps each authoring file at 16 KiB to preserve focused progressive
disclosure.

Skill resources are registered both with `McpServer.registerResource` and with the server's shared
`resources/read` dispatcher. Static skill subscribe/unsubscribe requests are accepted as no-ops,
matching other fixed resources.

## Generation and validation

`docs/authoring/manifest.json` explicitly allowlists the served skill directories. The deterministic
generator:

- parses complete YAML 1.2 frontmatter and requires JSON-compatible values;
- enforces Agent Skills naming and directory matching;
- rejects symlinks, unsupported/binary files, unsafe paths, missing relative links, duplicate paths,
  and case/Unicode-normalization collisions;
- verifies canonical UTF-8 round trips and project/SEP size limits;
- sorts resources deterministically and computes every digest and size from raw bytes; and
- writes `packages/mcp-server/src/generated/authoring-skills-content.ts`.

A normal `pnpm build` runs the shared authoring-skills ensure step before either published consumer
builds, so stale generated bytes cannot ship. `pnpm generate:authoring-skills` remains the explicit
regeneration command. Commit source and generated output together; the drift test byte-compares a
fresh render with the checked-in module.

## Cutover

The old `docs` tool, its input/output schemas and exports, `agentprism://docs/*` resources, generated
topic bundle, topic index, and standalone filesystem skill are removed in the same release. There is
no alias, fallback reader, or compatibility parser. Clients that do not implement the Skills
Extension still see ordinary `skill://` resources if they browse `resources/list`, but they do not
receive the retired model-facing documentation tool.

The `author-workflow` prompt remains a compact, user-controlled task frame. It tells the assistant to
activate `skill://agentprism-workflow-authoring/SKILL.md` through the host's skill-loading path and
never embeds the skill or treats an ordinary `resources/read` as activation.
